What it does

Employees ask for materials. The system checks every warehouse, issues what is in stock through standard Odoo transfers and sends the missing quantities to purchasing, where they become purchase orders with their own approvals. Everything is traced back to the request, and to the project it belongs to.

✅

Workflow

  1. Employee Request: Draft → Department → Warehouse → Budget → Approved.
  2. Split: automatic or manual, into stock transfers (what is available) and purchase orders (what is missing), one per warehouse and per project.
  3. Employee Purchase Order: starts as an RFQ you can print or email, then Manager Approval → Budget Approval → Open.
  4. Budget rejection: the order goes to Budget Control, is corrected and resubmitted straight back to Budget Approval.
  5. Execution: a real Odoo purchase order, receipts (with optional inspection approval) and vendor bills. The request moves to Processing, Partially Done, Closed.

Projects & stock lock NEW

Materials bought for a project should not quietly disappear into another one. The module keeps track of what each project holds and asks for approval before anyone takes it.

Project filled automatically

Stock orders take the project of the request line. Receipts take it from the purchase order. A request with several projects creates one stock order and one purchase order per project.

Stock held per project

Held = received for the project + allocated by hand − issued to it, per warehouse and product. Always visible in Project Stock Report.

Approval to issue

A transfer that takes stock held by another project is blocked: no reservation, no validation. The requester gives a reason, the owner project's manager approves or rejects with a reason.

Manual allocations

Set aside stock that is already in the warehouse for a project, and release it when it is no longer needed.

Approval history

Who asked, who approved or rejected, when and why, kept in a dedicated report.

Safe by design

The project of a validated transfer cannot be changed, and an approval is cancelled automatically if quantities or the project change afterwards.

Automatic requests respect the lock too. When a request is split, stock held by other projects is not offered to the line: the missing quantity goes to purchasing instead.

Reservation, Replace & Release Back NEW

Built from the project inventory meeting: stock is reserved for a project, moved between projects with approval and returned to general stock when it is no longer needed.

Reserve for a project

From the General Projects Warehouse (set in Settings), or directly to the project when it is received on the project's purchase order.

Replace action

A Replace Stock button on the project pulls products from any warehouse. If the stock belongs to another project, the owner's approval is required.

Purchase order alert

The approval shows how much is taken from which project and what it keeps, so you know when a purchase order may be needed for them.

Release Back

When a project needs nothing more, release its reservation and the quantity returns to general stock.

Project stock report

Warehouse, project, product, received, allocated, issued and held quantity, from Inventory and from the app.

Expiry control

A daily notice before lots expire, plus an Expiry Date Report with expired / within 30, 60, 90 days filters and a dashboard tile.

FAQ

Does it change Odoo core?

No. It extends standard models and views; transfers, purchase orders, receipts and bills are the normal Odoo documents.

What stock is locked for a project?

Stock received on purchase orders that belong to the project, plus quantities allocated by hand. Stock that was already in the warehouse is free until you allocate it.

Can I turn the project lock off?

Yes, in Settings → Employee Requests → Project Stock Lock. Projects are still filled on documents and shown on the reports.

Who approves a cross-project issue?

By default the project manager of the project holding the stock, falling back to the users chosen in the settings.

Does it work with several warehouses and companies?

Yes. Availability, holds and the report are computed per warehouse and per company.
