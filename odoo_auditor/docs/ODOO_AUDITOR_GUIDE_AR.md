# Odoo Auditor 19 — الوصف الكامل ودليل التشغيل

**الاسم التقني:** `odoo_auditor` · **الإصدار:** 19.0.1.0.0 · **المطوّر:** Eng. M.Aboelmagde · **الترخيص:** OPL-1
**الاعتماديات:** `base` + `mail` فقط. التكاملات مع Accounting / Sales / Purchase / Inventory / MRP / HR اختيارية؛ أي قاعدة تطبيقها غير مثبّت بتتخطى نفسها مع تحذير.

> حالة التجربة: المديول اتفحص فحص ثابت (صياغة Python وXML) ولسه محتاج تثبيت وتجربة على نسخة Odoo 19 تجريبية قبل الإنتاج.

---

## 1. الفكرة العامة

مديول مراجعة داخلية ورقابة مستمرة **للقراءة فقط**. بيفحص بياناتك بقواعد جاهزة، ويطلّع **ملاحظات (Findings)** مع **دليل** محفوظ وقت الاكتشاف، ويتابعها لحد الإغلاق بإجراءات تصحيحية وتقارير.

**اللي بيعمله:** مراجعة آلية، مراقبة مستمرة، قواعد قابلة للضبط، متابعة الملاحظات والأدلة والإجراءات، خطط وبرامج وأوراق عمل، سجل مخاطر وضوابط، مراجعات صلاحيات، قوائم إقفال، داشبورد وتقارير.

**اللي مبيعملوش أبدًا:** لا بيرحّل ولا بيلغي ولا بيعكس قيود، لا بيغيّر مخزون، لا بيوافق أو يرفض مستندات، لا بيعدّل مرتبات أو BOM أو تكاليف، ولا بيعدّل أي سجل علشان يخفي ملاحظة. بينشئ سجلاته الخاصة بس.

**مبدأ مهم:** كل ملاحظة **مؤشر يحتاج مراجعة بشرية** وليست حكمًا بوجود خطأ أو احتيال. كل قاعدة بتوضح طبيعتها: تضارب مؤكد / استثناء من سياسة / مؤشر مخاطر / يحتاج تحقيقًا.

## 2. التثبيت

1. انسخ فولدر `odoo_auditor` في مسار addons، أو فك الـ zip هناك.
2. Apps > Update Apps List ثم ابحث عن **Odoo Auditor** وثبّته (أو `-i odoo_auditor`).
3. الاختبارات: `odoo -d <db> -i odoo_auditor --test-tags odoo_auditor`. أهم اختبار `test_no_rule_errors_on_this_database` لأنه بيشغّل كل القواعد ويكشف أي اختلاف في أسماء الحقول.
4. الترجمة العربية: `-u odoo_auditor --i18n-overwrite -l ar` ثم أعد تحميل المتصفح (لتحديث الداشبورد والـ assets).
5. مكتبة `xlsxwriter` مطلوبة لتصدير Excel (موجودة عادةً مع Odoo).

## 4. الإعداد الأولي (5 دقايق)

1. أضف نفسك لمجموعة **Audit Manager** (Settings > Users).
2. **Odoo Auditor > Configuration > Quick Setup**: راجع الحدود (مبالغ، أيام، نسب)، اختار التكرار (يدوي/يومي/أسبوعي/شهري)، اضغط **Apply**. القواعد اللي تطبيقاتها مثبّتة بتتفعّل.
3. **FIN009** (أرصدة حسابات التسوية) معطّلة افتراضيًا: افتح القاعدة وحط الأكواد في *Extra parameters* مثل `{"codes": ["101404"]}` ثم فعّلها.
4. **SOD001** (الصلاحيات المتعارضة): عدّل الأزواج من *Extra parameters* بصيغة `{"pairs": [["purchase.group_purchase_manager", "account.group_account_manager"]]}`.
5. اختياري: حدّد **Owner** لكل قاعدة؛ يُسند تلقائيًا كمراجع مسؤول ويظهر له نشاط (Activity) عند الملاحظات العالية/الحرجة.

## 6. تشغيل مراجعة

1. **Audits > Run Audit**.
2. اختار الشركة والفترة (من/إلى) والمجال أو القواعد.
3. **Run in background** (مفعّل افتراضيًا): يدخل الطابور ويعالجه الكرون، وشاشة التشغيل بتعرض **شريط تقدم** واسم القاعدة الحالية. اقفله لو عايز تنفيذ فوري.
4. تفتح شاشة التشغيل: الحالة (مسودة ← في الانتظار ← قيد التشغيل ← تم/فشل)، عدد الملاحظات حسب الخطورة، الأخطاء/التحذيرات، لقطة الإعدادات وإصدارات القواعد.

**معلومات تشغيلية:**
- إعادة التشغيل آمنة: الملاحظة بتتعرف ببصمة (قاعدة + مستند) فلا تتكرر.
- مراجعتان في نفس الوقت لنفس الشركة ممنوعتين (قفل).
- قاعدة بتفشل ما بتوقفش التشغيل؛ بتتسجّل `[ERROR]` في سجل التشغيل وتكمل الباقي.
- **المجدول:** كرون يومي `run scheduled rules` بيشغّل القواعد اللي حان موعدها (غير اليدوية) ويبعت إيميل ملخص لمنشئ التشغيل. كرون تاني بيعالج الطابور، وكرون يومي لتصعيد الإجراءات المتأخرة.
- تصدير Excel: زر **Export to Excel** في شاشة التشغيل (أوراق: ملخص + ملاحظات).

## 8. التعامل مع الملاحظات

**مسار الحالات:** جديدة ← تم الفرز ← قيد التحقيق ← بانتظار رد الإدارة ← إجراء مطلوب ← بانتظار التحقق ← مغلقة. بالإضافة لـ **مرفوضة** (مكررة/إيجابية كاذبة) و**أُعيد فتحها**.

- تغيير الحالة بأزرار سير العمل فقط (مفيش تعديل مباشر).
- **Create Corrective Action:** يفتح إجراء جاهز (عنوان، مسؤول، موعد خلال 14 يوم، السبب الجذري).
- **الإغلاق** (مدير فقط): الملاحظات العالية/الحرجة تتطلب إجراءات **موثّقة التحقق**، ومالك العملية/صاحب الإجراء **ما يقدرش** يغلقها (فصل مهام).
- **Reject:** مدير فقط وبمبرر مكتوب.
- **Ignore in Future:** رفض + تسجيل استثناء بسبب؛ الحالة متتبلغش تاني. لإعادة الإبلاغ: أرشف السجل من *Configuration > Exclusions*.
- **إعادة الفتح التلقائي:** لو ملاحظة مغلقة واتكتشفت نفس الحالة في تشغيل جديد.
- **العرض:** Kanban (بالحالة)، قائمة، Graph، Pivot. فلاتر: مفتوحة، ملاحظاتي، عالية/حرجة، غير مسندة، متأخرة، أُعيد فتحها.
- **زر المصدر** يفتح المستند الأصلي. **Export to Excel** من Action على القايمة.
- **درجة المخاطر** = وزن الخطورة (5/25/50/75/95) × معامل الطبيعة (1.0 / 0.9 / 0.7 / 0.6).
- **تقرير PDF** لكل ملاحظة من Print.

## 9. الأدلة (Evidence)

- مع كل ملاحظة بيتولّد **Snapshot تاريخي** للقيم وقت الاكتشاف + **بصمة SHA-256**، غير قابل للتعديل أو الحذف، ومميز بوضوح عن الحالة الحالية للمستند.
- تقدر تضيف أدلة يدوية (مستند، تأكيد، ملاحظة ميدانية، مقابلة) بمرفقات، وحالة تحقق، ودرجة سرية (داخلي/سري/مقيّد). المقيّد/السري مرئي لمجموعة Confidential والمدير.

## 10. الإجراءات التصحيحية

مفتوح ← قيد التنفيذ ← مكتمل ← تم التحقق (أو ملغي). ملاحظات الإكمال إلزامية، والتحقق للمدير فقط **وبشرط أن يكون غير صاحب الإجراء أو من أكمله**. كرون يومي يصعّد المتأخر (عدّاد + سجل تصعيد + نشاط للمسؤول). تقرير PDF للإجراءات.

## 11. التخطيط والمراجعة الميدانية

- **Audit Plans:** سنة/فترة، هدف، نطاق، تقييم مخاطر، فريق، ساعات، اعتماد (مدير)، استنتاج.
- **Programs / Workpapers:** إجراءات، طريقة العينة (كاملة/عشوائية/تقديرية/إحصائية) مع الـ seed وحجم المجتمع والعينة المحفوظة، الاختبار والنتيجة والاستثناءات، ربط بملاحظات وأدلة، **الإعداد والمراجعة بشخصين مختلفين**.
- **Checklists:** قوائم إقفال فترة/سنة تتولّد جاهزة، ولا تُغلق قبل إنجاز كل البنود (مع من أنجز ومتى).
- تقرير PDF للخطة بالبرامج وأوراق العمل.

---

## 12. المخاطر والضوابط والصلاحيات

- **Risk Register:** الاحتمالية × الأثر (1–25)؛ نطاقات: ≤6 منخفض، ≤12 متوسط، ≤19 عالٍ، أعلى حرج. **الخطر المتبقي** = الكامن × (1 − تخفيض أقوى ضابط مرتبط).
- **Controls:** نوع (وقائي/كشفي/تصحيحي)، تكرار، مالك، فعالية التصميم والتشغيل (تخفيض 70% فعّال، 40% جزئي، صفر غير فعّال)، قواعد مرتبطة.
- **Access Reviews:** *Generate Conflicts* يلتقط المستخدمين ذوي الصلاحيات المتعارضة، تسجّل قرارًا لكل سطر (إبقاء بضابط تعويضي / طلب إلغاء / تصعيد) بمبرر. **المديول لا يغيّر صلاحية أحد.**

## 13. الداشبورد والتقارير والإشعارات

- **Dashboard (OWL):** عدد الملاحظات المفتوحة، الحرجة، العالية، الإجراءات المتأخرة، أعمدة حسب الخطورة والمجال، أنتج القواعد، آخر التشغيلات؛ كل عنصر يفتح القايمة المفلترة. يدعم **الوضع الفاتح والمظلم** تلقائيًا.
- **PDF:** ملاحظة، ملخص تشغيل، خطة، إجراءات. **Excel:** تشغيل أو ملاحظات محددة.
- **إشعارات:** نشاط للمراجع عند ملاحظة عالية/حرجة، وإيميل ملخص للتشغيل المجدول، وتصعيد الإجراءات المتأخرة.
- **Web icon:** أيقونة التطبيق في قائمة التطبيقات.

## 14. سجل التدقيق (Audit Log)

سجل محمي (إضافة فقط، لا تعديل ولا حذف) لتغييرات سجلات المديول: المستخدم، الوقت، العملية، قبل/بعد، السبب، والملاحظة المرتبطة. **لا يسجّل** تغييرات بقية موديلات Odoo.

## 15. حل المشاكل الشائعة

| العَرَض | الحل |
|---|---|
| قاعدة بتظهر "Skipped: required model not installed" | التطبيق المطلوب غير مثبّت؛ طبيعي |
| `[ERROR]` في سجل التشغيل | غالبًا اختلاف اسم حقل في إصدارك؛ ابعت النص كاملًا للتعديل |
| "Another audit is currently running" | في تشغيل شغال لنفس الشركة؛ انتظر أو أعد المحاولة |
| الداشبورد فاضي/مش بيظهر | حدّث المديول وأعد تحميل المتصفح (assets) |
| مفيش ملاحظات HR | تحتاج مجموعة Confidential أو التطبيق غير مثبّت |
| FIN009 بتعطي تحذير | لازم تضبط `codes` في Extra parameters |
| ملاحظة اتجاهلت ورجعت محتاجها | أرشف سجل الاستثناء من Exclusions |
